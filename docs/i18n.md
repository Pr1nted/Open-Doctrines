# Translating OpenDoctrines

Twenty languages besides English, and the interface, the doctrine data, the
credits and nine dialogue scripts in every one of them.

There is no string table in the source. The words are written where they are
drawn, English is the key, and everything below exists to make that arrangement
survive twenty languages.

## The three moving parts

| | |
|---|---|
| `tools/i18n_extract.py` | reads the source and the data files, writes `data/lang/en.json` — the set of things to translate |
| `tools/i18n_sync.py` | copies that set into the other twenty files, `--report`s how complete each is, `--lint`s them |
| `src/i18n/` | the runtime: the table, the transliterator, the glyph atlas, the shapers |
| `data/lang/<code>.names.json` | proper nouns — countries and ethnic groups — written by hand, not generated |

`en.json` is generated. Never edit it: run the extractor.

```bash
python3 tools/i18n_extract.py     # source  -> data/lang/en.json
python3 tools/i18n_sync.py        # en.json -> the other twenty
python3 tools/i18n_sync.py --report
python3 tools/i18n_sync.py --lint
```

## How a string gets translated

`DrawText` and `MeasureText` are shadowed (`src/i18n/Text.h`) and look every
string up as they draw it. So a plain literal needs nothing:

```cpp
DrawText("Economy", x, y, 20, WHITE);        // translated, no T() required
```

`T()` is needed where the literal does **not** sit on a drawing line — because
the extractor has to see it, or because the value is composed before it is
drawn. Four shapes come up:

```cpp
// 1. Composed. The FORMAT STRING is the key; TextFormat runs after the lookup.
DrawText(TextFormat(T("Annual Income: %.1f"), income), ...);

// 2. Parked in a variable on the way to being drawn.
const char* hint = page == Hub ? T("Esc  back to menu") : T("Esc  back");

// 3. An ARGUMENT. The sentence being translated does not translate what
//    goes into it.
TextFormat(T("%s accepted your offer of %s"), properName(name), T(phrase));

// 4. A struct table of labels, which the extractor cannot read.
LegendItem items[] = { {T("Self"), blue}, {T("War"), red} };
```

**A country name is never a plain string.** It goes through
`od::i18n::properName()`, which knows the forms a generated state's name is
built from (`Socialist Union of %s`) and transliterates only the invented root.

**`T()` must not run before a language is loaded.** A `const` table at
namespace scope is initialised at startup, so wrapping its labels freezes
English in. Those are collected by name in `LABEL_TABLES` and looked up when
the row is built — see `makeSettingLabel()` in `Game.cpp`.

## Finding what is still English

Grepping for literals finds four thousand error messages and protocol
constants, and misses the text that arrives as an argument. So the game tells
you instead. Every drawn string passes through one function, and that function
can log the ones that never found a translation:

```bash
OD_I18N_AUDIT=/tmp/audit.txt ./OpenDoctrines
```

Anything drawn that is not a key, is not already a translation, and is not just
digits and punctuation is written there once. Off by default; when it is off it
costs one null check per drawn string.

The two headless modes walk most of the interface without a person at the
keyboard, which is the quickest way to sweep it:

```bash
OD_I18N_AUDIT=/tmp/walk.txt OD_WALK_LANG=ja ./OpenDoctrines --tutorial-walk
OD_I18N_AUDIT=/tmp/tour.txt ./OpenDoctrines --screenshots out/ "save.odsv"
```

Composed results (`"Resolution: 1600x900"`) appear in the report and are
usually fine — read them for **English content**, not for their presence. A
line that is half translated and half English is the interesting kind:
`"Якщо оголосите: State no reason"` was how the war-goal table was found.

## Proper nouns

A country or an ethnic group does not go through the table. It goes through
`od::i18n::properName()`, which:

1. peels off a form it recognises — `Republic of %s`, `%s Republic`, `Free %s`
   and about sixty others — and translates that part,
2. looks the bare name up in `data/lang/<code>.names.json`,
3. and only if there is no entry, transliterates it.

Step 3 is what lets an invented country from the map editor read correctly in
Japanese. Step 2 is what stops a real one reading like a phonetic guess: every
language file carries the 252 countries, and the 245 ethnic groups that have a
settled exonym. Groups outside that list — most of the 1123 the minority screen
can draw — fall through to step 3 on purpose, because a transliteration of
`Akposso` is right and an invented translation would not be.

These files are written by hand and never generated, so `--lint` treats them
as suspiciously as the interface file: wrong-script characters, and any Latin
letter at all in a language that does not write in Latin.

## When one English word is two words

`T("Port")` was the harbour in the province panel and the TCP port in the
multiplayer dialog. One key cannot be both, so whichever meaning a translator
picked, the other screen was wrong -- and all twenty were wrong somewhere.

A call site that is ambiguous names its meaning after a `|`:

```cpp
T("Port|the harbour a ship is built in")
T("Port|the network port the host listens on")
```

The whole string is the key, so the note reaches the language files and the
two meanings become separate entries. Only the part before the `|` is ever
drawn -- in English, and in a language that has not translated it yet.
`--lint` refuses an untranslated context key, because that fallback is the
bare English, which is the one word that cannot be right in both places.

## Does it still fit?

A widget sized for English is sized for the shortest language in the set, and
the failure is silent: `drawActBtn` CENTRES its label, so a label wider than
its button does not clip -- it hangs out of both ends over whatever is beside
it. "Cancel Request Mutual Guarantee" does that in English, at 170px of label
in a 154px button, and ninety-three translations did the same. The widget was
wrong; translation only made it obvious.

`odText::fitToWidth` is the fix at the draw: it drops a point or two of type
first and cuts with an ellipsis only when even the floor size will not do.
Use it anywhere text is centred in a box it does not control.

Two things watch it. `OD_I18N_FIT=<path>` reports what overflowed in the
language the game is running in — the sibling of `OD_I18N_AUDIT`, same bargain,
one null check per call when it is off. But that only sees what a screen
happened to draw, in one language, so it is a floor and not a proof.

`OD_I18N_FIT_MANIFEST=<path>` records the BOX instead of the failure: where it
is, how wide, at what size. Run it once in English and `tools/i18n_fit.py`
measures every language's version of every string that box can hold —
through the game, via `--measure-text`, because nothing outside it can measure
honestly. A translation with non-Latin characters is measured against that
language's glyph atlas, a pure-ASCII one goes to raylib's variable-width font,
and Urdu goes through HarfBuzz; an offline model of all three was wrong by up
to 17% on the first strings it was checked against, which is the whole margin
a button has.

```bash
OD_I18N_FIT_MANIFEST=/tmp/manifest.tsv \
    ./OpenDoctrines --screenshots /tmp/shots data/saves/Modern\ Day.odsv
python3 tools/i18n_fit.py
```

The tool separates a label that SHRINKS to fit, which nobody notices, from one
that is cut, which is a bug. Two things to know about the floor:

  raylib clamps `DrawText` and `MeasureText` to a minimum size of 10, so a
  pure-ASCII label cannot shrink past it however small a size is asked for.
  Text on the glyph atlas scales smoothly and has no such floor.

  `needsAtlas()` switches fonts on the first byte above 127, looking at the
  whole string -- so appending U+2026 to an English label moves it off
  raylib's font onto unifont, and the typeface changes because the text was
  shortened. `fitToWidth` cuts ASCII with three ASCII dots for that reason.

Regenerate the manifest whenever a widget is added or resized; a box nobody
called `fitAudit` from is a box nobody is checking.

## What the checks catch

- `i18n_sync.py --lint` — format specifiers that differ from the English (a
  `%s` too many reads a pointer nobody passed), invisible bidi controls, a
  Latin letter inside a Cyrillic word, and characters from a script the
  language does not use. The `.names.json` files are checked too, plus a
  stricter rule there: no Latin letters at all in a non-Latin language,
  which is what caught `الفاروaz` sitting in the Arabic names file.
- `tools/dialog_check.py` — the `.oddlg` scripts: page structure, `::`
  directives verbatim, choice targets, speaker ids, `§` balance.
- `tools/check_policies.py` — among other things, that every effect line in
  `data/policies.json` has a form in `kTradeoffForms` to be translated by.
- `tools/i18n_fit.py` — every translation measured against the box it is
  drawn in, using the game's own measurement. Needs a manifest; see above.
- `tools/i18n_quality.py` — what the others cannot see: half-width
  punctuation inside Japanese or Chinese, ASCII commas in Arabic, a broken
  ellipsis, `{tag}` placeholders that differ, a lost edge space, and (as
  warnings) one concept translated two ways, values left in English, and one
  translation serving two different English strings.
- `tests/locale_test.cpp` — transliteration written out in full, the name
  forms, that a language without a transliterator keeps the Latin name,
  that a names-file entry beats the transliterator in every script, and that
  a `|` note is never drawn.

## Adding a language

1. `src/i18n/Locale.cpp` — add it to `kLanguages` (code, flag, endonym).
2. `tools/i18n_sync.py` — add the code to `CODES`. The script fails if the two
   disagree.
3. `python3 tools/i18n_sync.py` writes the empty file; fill it in. An empty
   value falls back to English, so a partial translation is safe to ship.
4. If it is not written in the Latin, Cyrillic, Japanese, Chinese, Korean,
   Arabic or Devanagari the atlas already builds, `setLanguage()` needs to know
   which codepoints to ask for.
5. `data/dialog/<code>/` for the nine scripts. Missing files fall back to
   English. `markup_demo` and `tutorial_pointer` are test cards for the
   textbox engine, not content, and are not counted as missing.
6. `data/lang/<code>.names.json` for the countries and ethnic groups. A
   missing file is not an error — every name then transliterates.
